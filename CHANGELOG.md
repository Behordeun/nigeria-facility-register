# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project aims for [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Nightly off-host backups. `scripts/backup_host.sh` copies the live register (gzipped, named `<time>-<fingerprint>` like the archives in `build/published/`) and a `pg_dump` of Superset's records to an OCI Object Storage bucket. It uploads through a write-only pre-authenticated request URL read from `NFR_BACKUP_PAR_URL` in `.env`, so the host holds no OCI login and can only add objects to that bucket. The URL is passed to curl on stdin and never appears in arguments, logs or errors. The register is copied once inside the container and its fingerprint read from that copy, so the name always matches the contents, even if a publish happens mid-backup. `bootstrap_host.sh` installs an `nfr-backup` systemd timer that runs it at 02:30 UTC; with the setting empty the script does nothing. Retention is a 30-day lifecycle rule on the bucket. DEPLOY_ORACLE.md covers setup, restoring the register through `restore_register.py`, restoring Superset with `pg_restore`, and a restore check that leaves the stack alone.

### Changed

- Every service in the compose stack restarts with Docker (`restart: unless-stopped`), so the register, Superset and the public dashboard come back on their own after a host reboot or a crash. A service stopped by hand stays stopped. `bootstrap_host.sh` enables Docker at boot on a host where Docker was already installed, and Superset's startup stops if its database upgrade or init fails, so the restart policy retries it until Postgres is ready instead of Gunicorn starting without them.

## [0.9.0] - 2026-11-10

### Added

- Releases deploy themselves. The `deploy` workflow runs when a GitHub release is published, or by hand for a given tag. It connects to the host over SSH with a key that `authorized_keys` pins to `scripts/deploy_host.sh`. That script fast-forwards the host's `main` to the tag and continues with the tag's own copy of itself. It then rebuilds the images, restarts the stack, waits for Superset to report healthy, re-imports the dashboard (and the public-viewer role when that account is configured) and checks that both UIs answer. It changes nothing when the tag is not a release on `main`, the host has local changes or is off `main`, or the host is already past the tag. The host key is verified, the job holds no repository permissions, the deploy settings live on a `production` environment that can require approval, and one deploy runs at a time. DEPLOY_ORACLE.md has the one-time setup.

### Changed

- The Oracle runbook covers launching the instance from the OCI CLI when the console reports no Arm capacity: setting up the CLI and an API key, creating the network, and trying each availability domain with the Always Free shape and size fixed, so a retry never falls back to a billable shape. It also notes that changing the availability domain on the console form can reset the shape, how to get a public IP when the wizard creates the network, re-running the bootstrap if the SSH session drops part way, an SSH config entry for the host, and alternative local tunnel ports for when the stack also runs locally.
- A restore that fails at any step after it archives the live register, including creating its staging file, removes that archive entry again, so `build/published/` holds exactly the registers it held before the attempt. A test covers a failure to create the staging file.
- `superset_config.py` records why `SQLALCHEMY_DATABASE_URI` stays a rendered string rather than a SQLAlchemy `URL` object: Superset 4.1.1's migration step (`superset db upgrade`) treats the setting as text. No behaviour changes.

### Notes

- No published table or column changes; the 0.8.0 register serves this release as it is.
- To upgrade by hand: pull, rebuild both images (`docker compose build`), run `docker compose up -d`, then re-run `make dashboard`. This is the first release that carries `scripts/deploy_host.sh`, so a host set up for automatic deploys needs this one update by hand; later releases deploy through the `deploy` workflow (DEPLOY_ORACLE.md, "Automatic deploys").

## [0.8.0] - 2026-11-10

### Added

- Public access to the dashboard. A `cloudflared` service (compose profile `public`) publishes Superset alone on an HTTPS address through a Cloudflare Tunnel, so the host opens no inbound port; it shares a network only with Superset, keeping the Dagster UI, Redis and Postgres out of its reach. Setting `SUPERSET_PUBLIC_URL` turns on Superset's proxy handling, an HTTPS-only session cookie with a 12-hour lifetime and a sign-in rate limit kept in Redis. `make public-viewer` (`scripts/superset_public_viewer.py`) creates the shared `public-viewer` account with a `Public viewer` role built from an explicit allowlist: it opens and filters the dashboard and reaches only its datasets, with no SQL Lab, Explore, data export, drill to detail, server-side downloads, or changes to the shared account. A test holds the allowlist. DEPLOYMENT.md has the setup and what the role does not prevent, and ADR 0003 records the decision.
- `docs/DEPLOY_ORACLE.md`, a runbook for running the compose stack free on one Oracle Cloud Always Free Arm instance (1 OCPU, 6 GB, sized so it is not reclaimed as idle), and `scripts/bootstrap_host.sh`, which prepares a fresh Ubuntu 22.04 or 24.04 host: Docker Engine and the compose plugin from Docker's apt repository, git, make and python3-yaml for `make dashboard PY=python3`, a swap file, unattended security upgrades and docker group membership. The script is idempotent.
- `scripts/build_espen_lga.py` rebuilds `data/derived/ntd_espen_lga.csv` from ESPEN's public IU-level download route, the same one the monthly upstream check reads, instead of exports held outside the repository. It downloads the five disease exports into `data/raw/espen/` (never committed, since ESPEN is non-commercial), maps each IU to its LGA through the master index, and compares the result with the table's pinned sha256, refusing to overwrite it unless `--update` is given. The rebuild reproduces the committed table byte for byte, so no published value changes. The ESPEN derivation moves to `nfr.enrichment.espen`.
- Failure and upstream alerts. When `NFR_ALERT_WEBHOOK_URL` is set (an incoming webhook for Slack, Teams, Mattermost, Google Chat or Discord), a failed refresh posts its vintage and root cause, such as a gate rejection, a failed dbt test or a held vintage, and the monthly upstream check posts any release waiting for review or publisher it could not read. Each distinct failure is sent once until a refresh publishes again. Alerting never changes a run's outcome, uses only the standard library, and never logs the URL. Compose passes the variable through to the Dagster services; it is empty by default.
- The last three published registers are kept in `build/published/`, and `scripts/restore_register.py` rolls back to one (`--list`, `--restore <name>`; `make registers` and `make restore REGISTER=<name>` locally). Each publish hard-links the outgoing register into the archive before the atomic rename, so keeping it costs no copy. A restore swaps the chosen register onto the live path atomically, archives the one it replaces, clears Superset's chart cache, and holds the rolled-back vintage: no refresh, scheduled or manual, publishes it again until its inputs change, a different register is published, or the hold is released with `--release-hold`. The runbook is in DEPLOYMENT.md.
- ADR 0004 records how the priority score is built (equal-weight ordinal points, burden as the highest known rank, relative coverage and malaria quartiles, fixed tier cut-offs) and what a change to it requires. `scripts/score_sensitivity.py` re-ranks the scored LGAs under alternative weightings (each part dropped, each doubled, each rescaled to 0-1) and reports how many high-tier LGAs stay in the top group and the overlap of the two groups; it opens the register read-only. ADR 0005 records why the readable text (`priority_reasons`, `lga_summary`) is built in dbt and when to revisit that. No published value changes.

### Changed

- The Dagster image is built from an allowlist. `.dockerignore` now ignores everything and re-includes only the packaging files, `dagster.yaml`, `src/`, `dbt/`, `data/` (without `raw/`) and `scripts/`, so local files such as the `.env` file, editor and agent settings, and internal notes stay out of the image. Rebuild with `docker compose build webserver`.
- Every dbt model and seed is its own Dagster asset, and every dbt test on a single model is an asset check on it, through dagster-dbt. The asset graph shows the real model dependencies, and a failed refresh names the model or test that failed. The refresh is now `raw_sources`, the dbt model assets, and `published_register`, which runs the carry-over gate and the atomic publish that `dbt_models` ran before; the resolve-rate and carry-over checks move with it. The refresh job selects the `refresh` group. The build still writes only to the run's side database and publishes only after every model, test and the gate pass. The deployment image parses the dbt project at build time, and CI loads the Dagster definitions after the sample build. dagster and dagster-webserver move to 1.13.22, the first release line whose dagster-dbt (0.29.22) admits the dbt-core 1.12 floor. ADR 0002 records the decision.
- `make dashboard` checks that the register exists in the Superset container before importing. On a fresh stack, where no refresh has published a register yet, it stops with a one-line pointer to the `refresh_register` job instead of a long Superset traceback; a Docker failure is still reported as such. The path is read from the bundle's own connection.
- `data/sources.yml` records the flood-exposure flags as a fixed snapshot: derived from NASA MODIS products in a separate project, pinned by sha256 with their source file, and not refreshed by this pipeline. ATTRIBUTION.md and DATA_CONTRACT.md say the same.
- The Dagster orchestration is split by concern: `config` (paths, run tags, the input fingerprint), `gates` (quality gates and the publish step), `assets`, `checks`, `jobs`, `schedules` and `sensors`, with `definitions` only registering them. Dagster loads the same assets, checks, jobs, schedules and sensors with the same settings, and `nfr.orchestration.definitions` stays the entry point, so deployments need no change.
- The refresh fingerprint covers every input that shapes the register: the GRID3 geopackages, every file in `data/frame/` and `data/derived/`, a digest of the dbt models, macros, seeds and project files, and the population year. The sensor rebuilds when any of them changes, so a new enrichment table, an edited model or the turn of the year publishes without waiting for the weekly schedule, and the live register records the full set it was built from. Each run snapshots the frame and derived tables with the geopackages, fixes its population year once (carried from the sensor as a run tag) and passes it to dbt, so a run builds exactly what it fingerprinted. Expect one rebuild after upgrading, since every fingerprint changes.
- Local builds go to `build/scratch.duckdb`: `make build`, `make sample` and a bare `dbt build` no longer write the published register path, and `make clean` leaves it alone. `make setup` installs from the frozen lockfile with `uv`, matching CI, and `make test` runs what CI runs (unit tests, then the sample transform and its dbt tests), failing when any of them fails.
- Every map draws a measured zero. Non-endemic LGAs (rank 0) and LGAs with access risk 0 take the first colour of their map (pale yellow on the disease maps, pale red on the access map), so blank means only "not measured". The deck.gl Polygon layer leaves a polygon unfilled when its value is 0, so each map whose lowest band starts at 0 maps 0 to 0.001 in its metric; a bundle test keeps it so.
- The dashboard reads more cleanly. Every chart sits on a plain white card with a hairline border and a rule under its title, tables have a tinted header row, and the explanatory notes sit on a pale teal panel. The disease maps run two to a row and every half-width map frames the whole country, the northeast included. The malaria map gains a legend, the priority score legend ends at 11, and the access map's colour key moves to its note. The LGA profile's 2030 line starts at zero, so a small decline no longer looks like a cliff, and single-series charts use the dashboard teal. The by-state table shows exact counts without in-cell bars, the access table shows flood exposure as Yes or No, all 37 states are labelled on the facilities-by-level chart, and the headline tiles' captions are shortened to read at one size.
- The Data status tab's sources and licences note credits every source the dashboard shows: WorldPop, the Malaria Atlas Project and NASA MODIS join GRID3, geoBoundaries and ESPEN.
- The Dagster image build keeps uv's cache in a BuildKit cache mount, so packages downloaded or built once are reused when a code or lockfile change rebuilds the dependency layer. `dbt-core-experimental-parser` fetches its platform wheel from GitHub releases at install time; with the cache that download happens once per machine and parser version. Builds that start from an empty cache, such as `docker compose build --no-cache`, retry the dependency install up to three times, 30 seconds apart, so a short upstream download outage does not fail the build.

### Notes

- No published table or column changes, and every value is the same as in 0.7.0. The refresh fingerprint now covers more inputs, so the first refresh after upgrading rebuilds and republishes the register once, with the same figures.
- To upgrade a running deployment: pull, rebuild both images (`docker compose build`), run `docker compose up -d`, then re-run `make dashboard`. The Dagster image now runs dagster 1.13.22 and the per-model dbt assets; the Superset image carries the public-access settings, which stay off until `SUPERSET_PUBLIC_URL` is set.
- New optional settings, all empty by default: `NFR_ALERT_WEBHOOK_URL` for failure and upstream alerts, and `SUPERSET_PUBLIC_URL`, `CLOUDFLARE_TUNNEL_TOKEN` and `SUPERSET_PUBLIC_VIEWER_PASSWORD` for publishing the dashboard. `.env` needs none of them for a local stack.

## [0.6.0] - 2026-11-08

### Added

- Malaria burden per LGA. `lga_coverage_burden` gains `malaria_year`, `pf_parasite_rate` (the P. falciparum parasite rate in children aged 2-10, 0-1) and `pf_incidence_per_1000` (clinical cases per 1,000 people a year), from the Malaria Atlas Project's 202608 release for 2025, and `lga_coverage_choropleth` carries both measures. Each is population-weighted on the WorldPop 2025 100 m grid, so dense urban LGAs smaller than one 5 km MAP cell still get their value; every LGA has one. `scripts/build_malaria_burden.py` builds `data/derived/malaria_lga.csv` from rasters pinned by SHA-256 in `data/sources.yml`. The map hover and the LGA profile (now 20 facts) include malaria. A dbt test checks the columns equal the source table, one year, and stay in range. Nationally the median LGA has a 24% parasite rate and 270 cases per 1,000 a year.
- The monthly upstream check also watches the Malaria Atlas Project malaria releases. It reads the Malaria WCS capabilities and reports a P. falciparum parasite-rate or incidence release dated after the pinned one (202608 today) as a new release to review; older releases, which MAP keeps listed, and products the register does not use are ignored. It runs as its own finding beside the travel-time check.

### Changed

- Malaria is the fourth part of the priority score. `priority_malaria_points` (0-3) scores the parasite rate by national quartile, highest quarter 3, the mirror of coverage points; it is relative because nearly every LGA sits in the same absolute prevalence band. `priority_score` now runs 0-11 (burden + coverage + access + malaria), and the tiers move to high 8-11 (74 LGAs, about the top tenth as before), medium 6-7 (269) and low 0-5 (431). The "why" text, map hover, LGA profile and dashboard wording follow, the score map's colours run in bands that match the tiers, and the LGA profile opens on the new highest-priority LGA (Bukkuyum, Zamfara).

### Notes

- Breaking for readers of the score: `priority_score` changes range (0-8 to 0-11) and `priority_tier` its cut-offs, so a stored score or tier from 0.5.0 is not comparable with one from this release. 34 of the 78 LGAs that were high priority stay high; the other 40 high-priority LGAs are new, because malaria varies independently of the NTD ranks (correlation 0.13). Re-run any analysis that filtered on the score or tier. The parts are all published, so the 0.5.0 score is still `priority_burden_points + priority_coverage_points + access_risk_score`.
- To upgrade a running deployment: rebuild the register (the new malaria source, columns and score), then re-run `make dashboard`. The compose stack and `.env` are unchanged.

## [0.5.0] - 2026-11-08

### Added

- The dashboard's readable text now lives in dbt, under the contract and its tests. `lga_coverage_burden` gains `priority_reasons` (why an LGA scores what it does) and `lga_summary` (the one-line LGA summary used as the map hover), and `lga_coverage_choropleth` carries `lga_summary`. A new `lga_profile_facts` mart holds everything the register says about each LGA as 18 ordered facts, so the LGA profile is a plain table instead of HTML built in the dashboard. dbt tests check that every LGA has its full fact set, that the reasons and summary agree with the score columns, and that the map hover equals the mart's text; on the real data the moved text is identical to what the dashboard built before.

### Changed

- The dashboard follows a planner's path. Tabs run Coverage, LGA profile, NTD burden, Access, Facility mix, Outlook, Version drift, Data status. The Coverage tab puts the ranked high-priority list right after the headline figures, and selecting an LGA there opens it on the LGA profile tab (a link that sets the LGA filter through the dashboard URL, so it can also be shared). The LGA filter's list narrows to the chosen state. Coverage drops the raw facilities-per-LGA map, which per-capita coverage supersedes, and the original priority flag's map and by-state count, kept while the 0-8 score was reviewed; `priority_high_burden_thin_coverage` stays in the published data.
- The dashboard reads more clearly. Maps frame Nigeria instead of West Africa. Colours carry the same meaning on every chart (colour-blind-safe for lineage, name agreement and facility level). Bars start at zero, and the LGA profile's 2030 trend is a line with exact values. Tables use thousands separators and two decimal places, the headline count is exact, and per-state bars are sorted largest first. The facility point map shows secondary and tertiary facilities, which primary points used to hide. The profile card loses its paging controls, the score-parts bar (the card already states the parts) and the superseded original flag column in the burden table. Presentation conventions are written down in DEPLOYMENT.
- Superset keeps its own records (users, roles, charts, dashboards) in a new `superset-db` Postgres service instead of SQLite, since the web server and the download worker both write to them. It needs a new required `SUPERSET_DB_PASSWORD` in `.env`. The register stays a DuckDB file that Superset only reads.
- Chart query results are cached in Redis for up to a day, and the refresh job empties that cache right after it publishes a new register, so the dashboard never shows figures from the previous register. A failed clear is logged as a warning and does not fail the refresh.
- pandas 3.1.1 and DuckDB 1.5.6, which move together: DuckDB 1.1 does not recognise pandas 3's default string type. The Superset image pins the same DuckDB, so the dashboard reads the register with the version that wrote it. A rebuilt register is identical to one built with pandas 2.2.3 and DuckDB 1.1.3, table for table and value for value.

### Notes

- The contract changes are additive: `priority_reasons` and `lga_summary` on `lga_coverage_burden` (and `lga_summary` on `lga_coverage_choropleth`), and a new `lga_profile_facts` mart. No published column changes meaning or type.
- To upgrade a running deployment: add `SUPERSET_DB_PASSWORD` to `.env`, run `docker compose up -d --build` (the Superset image changes and the stack gains `superset-db`), re-run `make dashboard`, and recreate any Superset users other than the admin, since Superset's records now start fresh in Postgres. The old SQLite file stays on the `superset_home` volume. Rebuild the register for the new columns and mart.

## [0.3.0] - 2026-11-07

### Added

- A population outlook. The new `lga_coverage_outlook` mart has one row per LGA for every WorldPop year the register carries (2025-2030), holding today's facility count fixed: population, facilities per 10,000 people, and the change in each from the register's own year, whose rows equal the published coverage mart. At today's count, national coverage falls from 2.59 facilities per 10,000 people in 2025 to 2.35 in 2030, LGAs below 2 per 10,000 rise from 207 to 267, and 47 LGAs at or above 2 today fall below it by 2030. A dbt test checks that every year covers the 774 LGAs once, the register-year rows match the coverage mart, facilities stay fixed and every rate and change recomputes. The dashboard adds an Outlook tab with national coverage by year, LGAs below 2 per 10,000 by year, and the LGAs falling below it by 2030.
- Facility mix per LGA. `lga_coverage_burden` gains facility counts by GRID3 level (`facilities_primary`, `facilities_secondary`, `facilities_tertiary`, `facilities_level_unknown`) and by functional status (`facilities_functional`, `facilities_not_functional`, `facilities_status_unknown`), `secondary_tertiary_per_100k_population`, `functional_status_known_share` and `not_functional_share`. A blank or Unknown level is counted as not recorded, never assigned one. GRID3 records functional status only in v3.0, so the not-functional share is taken over facilities whose status is known and is null, never 0, where none is. Nationally 5,745 facilities are secondary or tertiary (about 2.4 per 100,000 people, none recorded in 93 LGAs), 7,602 have no recorded level, and 303 of the 18,536 facilities with a recorded status are not functional or closed. `lga_coverage_choropleth` carries the rates and `register_summary` the national counts. A dbt test checks that the level and status counts each partition the facility count, that v2.0 LGAs carry no status, and that every rate recomputes. The dashboard adds a Facility mix tab: maps of secondary and tertiary facilities per 100,000 people and of the not-functional share (shading only LGAs with at least five facilities of known status), facilities by level per state, and a point map of facilities by level over a new `stg_facilities_authority` dataset; every map's hover and the Data status page gain the facility mix.
- The population year rolls forward with the calendar. `data/derived/access_population_lga.csv` now carries one row per LGA for every WorldPop R2025A year from 2025 to 2030, each derived from a raster pinned by SHA-256 in `data/sources.yml`, and the new `stg_access_population_lga` staging model selects one: the `population_year` dbt var when set, otherwise the build's calendar year capped to the years available. A weekly refresh in January therefore publishes the new year's population, per-capita rates, travel-time figures and priority scores without fetching anything, and `register_summary.population_year` states which year is live. New dbt tests check that every year covers the 774 frame LGAs once each and that exactly the expected year is selected; `scripts/build_access_population.py` builds every pinned year and refuses a year without a pin.
- A monthly upstream-release check. The `check_upstream_releases` Dagster job, scheduled for the 1st of each month, compares WorldPop's release index, the GRID3 Nigeria health-facility datasets on HDX, the Malaria Atlas Project's travel-time coverages and the ESPEN years published for Nigeria (through the portal's public download route, no key) with what `data/sources.yml` pins, and its asset check warns while a newer release waits for review, a publisher is unreachable (network errors are retried twice with backoff first) or one answers in an unexpected format (reported as unreadable, so a format change is not mistaken for an outage), or before the first check has run. It downloads nothing, never touches the register, and runs outside the refresh job.

### Changed

- The `refresh_register` job selects its two assets by name rather than every asset, so the upstream check can never run inside a refresh.
- The README opens with status badges: the CI workflow on `development` and `main`, the SonarCloud, GitGuardian and Amazon Q checks, all checks together, the latest release, the licence and the supported Python versions.
- Dashboard labels no longer name a fixed population year: population columns read "Population (WorldPop)", and the year is stated on the Data status page.

### Notes

- The register's population year now follows the calendar year within the WorldPop years carried (2025-2030). A register built in 2026 reports 2026 population, so population, per-capita rates, travel-time figures and priority scores move from the 2025 values published in 0.2.0 (for example 2.59 to 2.54 facilities per 10,000 people nationally). Set the `population_year` dbt var to build a specific year; `population_year: 2025` reproduces the 0.2.0 figures.
- Every other contract change adds columns or a new mart (`lga_coverage_outlook`); no published column changes meaning or type. To upgrade a running deployment, rebuild the register and re-run `make dashboard`.

## [0.2.0] - 2026-11-07

### Added

- A priority score per LGA. `lga_coverage_burden` gains `priority_score`, 0-8, the sum of `priority_burden_points` (0-3, the highest known endemicity rank across the five diseases), `priority_coverage_points` (0-3, by national quartile of facilities per 10,000 people, lowest quarter 3) and `access_risk_score` (0-2), plus `priority_tier` (high 6-8, medium 4-5, low 0-3) and `ntd_diseases_known`. A part that is not measured leaves the score and tier null, never low. On the current data 78 LGAs are high priority; the original flag marks 56, of which 14 are high. `priority_high_burden_thin_coverage` is unchanged and kept alongside for comparison. `lga_coverage_choropleth` carries the score, its parts and the tier, and `register_summary` counts high-priority LGAs. A dbt test recomputes every part, the score and the tier. On the dashboard the Coverage tab's priority count and map move to the score, the original flag's map sits beside a note explaining the score, the by-state and burden tables gain the score, and every map's hover summary shows the score's breakdown.
- Access and flood exposure per LGA. `lga_coverage_burden` gains the population-weighted travel time to the nearest health facility (`motorised_minutes`, `walking_minutes`, `walking_over_60min_share`, `access_population_share`, from the Malaria Atlas Project), the flood-event flags `flood_affected_2022_state` (state-level, named as such) and `flood_affected_2024` (LGA-level), `hard_to_reach` (a quarter or more of residents over an hour's walk from a facility) and `access_risk_score`, 0-2, one point each for `hard_to_reach` and the 2024 flood. The score is null, never 0, where travel time is not measured, and leaves out the 2022 flag, which marks 727 of 774 LGAs. 53 LGAs are hard to reach, mostly in Borno and Yobe, and two (Marte and Kala/Balge) score 2. `lga_coverage_choropleth` carries the access columns and `register_summary` counts hard-to-reach and 2024 flood-affected LGAs. A dbt test checks every access and flood column against its source and recomputes the score. The dashboard adds an Access tab with maps of the share of people over an hour's walk and of the access risk score, and a table of LGAs with access risk; every map's hover summary gains walking time, the 2024 flood flag and the score, and the Data status page an access line.
- Per-capita coverage. `lga_coverage_burden` gains `population` and `population_year` (WorldPop 2025), `births` (WorldPop 2015), `facilities_per_10k_population` and `facilities_per_10k_births`; a rate is null, never 0, where no facility matched the LGA, because a zero count there may be a name-join miss. Nationally the register holds 2.59 facilities per 10,000 people, and the rate exposes LGAs whose raw counts look ample for their size (Obio/Akpor: 114 facilities, 0.4 per 10,000 people). `lga_coverage_choropleth` carries the population and the per-capita rate, and `register_summary` the national population. A dbt test checks that both denominators equal their sources and each rate recomputes from its count. The dashboard adds a facilities-per-10,000-people map on the Coverage tab, population and per-capita columns in the by-state and burden tables, the per-capita rate in every map's hover summary, and a population line on the Data status page.
- Per-LGA population and access to healthcare as a tested raw source. `data/derived/access_population_lga.csv` gives, for each of the 774 LGAs, the 2025 WorldPop R2025A population (summed at 100 m) and the population-weighted travel time to the nearest health facility from the Malaria Atlas Project's 2020 maps, by motorised transport and walking only, plus the share of people more than 60 minutes' walk away. `scripts/build_access_population.py` fetches the rasters (never committed), checks each against a SHA-256 pinned in `data/sources.yml`, and refuses a table that misses a frame LGA, has an LGA with no population, or holds a negative time or an out-of-range share. LGAs with no population on valid travel-time cells get null travel figures, never 0. New dbt tests check frame coverage and those ranges. The derivation lives in `nfr.enrichment.access_population` so a scheduled refresh can reuse it; a failed download closes and removes its temp file, and `--print-hashes` only fetches and reports the upstream hashes, never building from unpinned files. rasterio is added as a dev dependency.

### Changed

- `make dashboard` (`scripts/superset_dashboard.py import`) now loads the bundle with Superset's assets importer, which overwrites the database connection, every dataset, every chart and the dashboard by UUID, so re-running it on an upgraded deployment brings existing charts and datasets in line with the bundle instead of updating only the dashboard layout. The import zip declares the assets bundle type; the committed bundle and `make dashboard-export` are unchanged. `tests/test_superset_bundle.py` checks the import zip and the in-container import program.

### Notes

- Every contract change in this release adds columns; no published column changes meaning or type. `priority_high_burden_thin_coverage` keeps its definition and sits beside the new `priority_score` and `priority_tier`.
- To upgrade a running deployment, rebuild the register and re-run `make dashboard`, which now updates the existing charts and datasets in place.

## [0.1.0] - 2026-11-06

### Added

- A pipeline overview diagram (`docs/images/pipeline-overview.svg`) at the top of the README's build section: source data, the DuckDB raw layer, dbt staging and marts, Dagster orchestration with the quality gate, and the read-only Superset dashboard. The three diagrams in `docs/ARCHITECTURE.md` (data flow, version lineage, orchestration and atomic publish) are redrawn as SVGs in the same style, replacing the Mermaid blocks.
- A Superset dashboard, "Nigeria facility coverage and NTD burden", committed as an import bundle in `superset/dashboards/nfr_coverage_burden/`. Four tabs: coverage (headline counts, facilities-per-LGA and priority-LGA maps, a by-state table), NTD burden (one map per ESPEN disease by endemicity rank with unknown LGAs left blank, the rank distribution per disease, a per-LGA burden table), version drift (lineage split, name agreement, lineage by state, the dropped/appeared review queue) and data status (a live summary of the published register read from `register_summary`, then the sources, licences and links to the project documents). State and facility-status filters apply across tabs. Hovering an LGA on any map shows its state, facility count and register version, the five endemicity ranks (unknown where no status is known) and the priority flag. The connection opens the register read-only. `make dashboard` imports it into the compose Superset (updating in place by UUID) and `make dashboard-export` writes edits made in the UI back to the bundle, selecting this dashboard by UUID. `tests/test_superset_bundle.py` checks that every reference resolves, the connection stays read-only, and every column a dataset or chart names exists in the dbt contract.
- A one-row `register_summary` mart describing the published register: when it was built, the GRID3 release date and state count for each version, facilities in the authority layer and how many sit in a resolved LGA, unmatched and priority LGA counts, LGAs with a known ESPEN status per disease, the latest ESPEN year, and the lineage totals. It is rebuilt on every refresh under an enforced contract, and a dbt test fails the build if it disagrees with the tables it summarises.
- The five per-LGA endemicity ranks on `lga_coverage_choropleth`, as columns and in the `geometry_feature` properties, so a map can colour LGAs by disease. They are exactly the `lga_coverage_burden` values.
- Per-LGA endemicity for five neglected tropical diseases in the coverage mart. `lga_coverage_burden` gains `sth_endemicity_rank_lga`, `sch_endemicity_rank_lga`, `lf_endemicity_rank_lga`, `oncho_endemicity_rank_lga` and `loa_endemicity_rank_lga`: an ordinal 0-3 rank from each LGA's latest known ESPEN status, null where the LGA was never reported with a known status, never 0. A new seed, `ntd_endemicity_rank`, maps every known label to the shared scale (prevalence bands for STH, schistosomiasis and Loa loa; programme stages for lymphatic filariasis and onchocerciasis), and a new contracted staging model, `stg_ntd_endemicity_lga`, holds the full per-LGA, per-disease detail (latest and latest-known label, year, rank, basis). The existing `sth_high_share_pct_state` column and the priority flag are unchanged. New dbt tests fail the build when a known ESPEN label has no rank, when the seed ranks a label twice or gives a disease more than one rank basis, when the staging table misses or repeats an (LGA, disease) pair or ranks an unknown status, and when a mart rank disagrees with staging. Derived from ESPEN (CC BY-NC-SA 3.0 IGO): non-commercial.
- Enrichment inputs for the burden-and-access phase, loaded and tested but not yet joined into any mart. Three derived per-LGA tables are committed under `data/derived/` and loaded as raw sources: `ntd_espen_lga` (ESPEN endemicity for five diseases, one row per LGA and disease, with the latest label and the latest non-"Unknown" label kept apart so an unknown is never read as a measured status; non-commercial, raw ESPEN not committed), `flood_event_affected_lga` (0/1 flood-exposure flags for the 2022 event at state resolution and the 2024 event at LGA resolution, labelled as such) and `births_lga` (WorldPop 2015 births per LGA, keyed on shapeID). `scripts/build_enrichment_sources.py` derives them read-only from the Geospatial monorepo files, collapses ESPEN's repeated target-population rows to one label per IU-year, aborts on conflicting labels, and checks every output covers exactly the 774 frame LGAs before writing atomically. New dbt tests fail the build when an input misses or adds a frame LGA (per disease and per event), duplicates an LGA, leaks an "Unknown" status into the known column, mixes resolutions within an event, or carries a zero or null births figure. Provenance, including the upstream file hashes, is pinned in `data/sources.yml` and the licences in `data/ATTRIBUTION.md`.
- Deduplication of repeated v3.0 facility records in the authoritative layer. GRID3 v3.0 assigns one `unique_id` to a small set of records that repeat it; most are byte-identical, and one pair agrees on every identity field but disagrees only on `functional`. `stg_facilities_authority` now keeps one row per `unique_id`, preferring a known `functional` over `Unknown` so the retained row is the more informative one and the choice is deterministic rather than sort-dependent. This holds the one-row-per-facility grain the coverage and lineage marts depend on. A guard test (`assert_v3_duplicate_ids_are_identical`) fails the build if two rows ever share a `unique_id` while differing on an identity field (name, LGA, level, coordinates), so the dedup can only collapse a status-only or exact duplicate, never silently drop a genuinely distinct facility.
- Pre-split LGA boundaries into single polygons. `scripts/build_lga_geometry.py` now explodes every MultiPolygon into one Polygon feature per part, so the vendored artifact is single Polygons only (800 features across the 774 LGAs; the 25 coastal and riverine LGAs with islands span more than one feature). A deck.gl polygon map layer rejects a MultiPolygon, so the split is what lets the choropleth render. The feature-count and geometry checks in the build script and the geometry tests now key on the 774 distinct shapeIDs rather than a flat 774-row count, and the choropleth completeness test keys on the 774 distinct (state, canonical_lga) pairs.
- GeoJSON Feature column on the choropleth mart. `lga_coverage_choropleth` now emits `geometry_feature`, a complete GeoJSON Feature string per LGA (type, geometry, properties), alongside the bare `geometry_geojson`. A deck.gl Geojson map layer reads `geometry` and `properties` off each row, so the bare geometry alone gives it nothing to key on; the Feature carries the coverage and burden attributes for colouring and tooltips. Both geometry columns are now `varchar` rather than `json`: a json-typed column returns a pre-parsed object from the driver, which a map layer that parses the string itself cannot consume.
- Optional Mapbox token for the Superset deck.gl basemap. The compose Superset service passes `MAPBOX_API_KEY` from `.env` (default empty, so the stack still boots without one); set it to a Mapbox public token for the map background. Documented in `.env.example` and the deployment doc.
- Apache Superset BI layer and a choropleth mart. A new dbt model, `lga_coverage_choropleth`, attaches each LGA's boundary polygon (as GeoJSON, read from the vendored geoBoundaries set via the DuckDB spatial extension) to `lga_coverage_burden`, one row per LGA with geometry, under an enforced contract and a test that all 774 carry a polygon. A Superset service in docker-compose reads the live register read-only (`duckdb://…?access_mode=read_only`) for the coverage-x-burden choropleth and the version-drift breakdown, pinned by image digest and published on localhost only. See `docs/DEPLOYMENT.md`.
- Container deployment for an always-on Dagster: a `Dockerfile` (uv, Python 3.12, project installed `--frozen --extra orchestration` so it matches CI) and a `docker-compose.yml` running the Dagster webserver and daemon from one image, sharing a DAGSTER_HOME and the `build/` database volume with `data/raw/` bind-mounted read-only. The webserver binds to localhost only (unauthenticated). The dev and CI loops are unchanged and need only uv + the lockfile. See `docs/DEPLOYMENT.md`.
- Vendored simplified LGA boundary polygons (`data/frame/nigeria_774_lga_boundaries.simplified.geojson`) for the forthcoming choropleth: 774 features derived from geoBoundaries NGA ADM2 (CC BY 4.0) by topology-aware simplification (topojson shared-arc, tolerance 0.01, ~1 MB vs ~9 MB raw), so adjacent LGAs keep matching borders with no slivers; keyed on shapeID and joining the master index 1:1. Committed rather than fetched because CC BY permits redistribution; regenerate with `scripts/build_lga_geometry.py` (needs the dev extra for topojson). The build validates the 774/774 frame join, rejects empty or non-polygonal geometry, refuses an in-place build, and writes atomically via a temp file. Tests pin the feature count, the 1:1 frame join, polygonal/valid/non-empty geometry, and that the geometry is genuinely coarser than full precision (vertex-count check, not file size alone).
- `make sample` target that runs the whole transform on the committed two-state sample fixture (load data/sample, then dbt build with the fixture vars) in one command with no external download, the same path CI uses to prove the transform on every PR.
- Immutable per-run snapshot of the raw inputs. A refresh copies data/raw/ into a run-scoped snapshot under build/snapshots/ (each file copied through a temp name and atomically renamed) and the loader reads the snapshot, not the live directory, so a change to data/raw/ after the run starts cannot alter what the run builds. When the sensor launched the run for a specific fingerprint, the snapshot's fingerprint is verified against that tag and the run fails fast on a mismatch, so a vintage that changed between the sensor's check and the load is never published under the old fingerprint. The published-vintage sentinel records the snapshot's fingerprint, and the snapshot is cleared when the run finishes. Snapshot creation rejects a raw input that symlinks outside the raw directory, so external data is never copied in and published; the snapshot is cleared on any raw_sources failure, not only the tag-mismatch path; and post-promote cleanup is best-effort, so a cleanup error after the data is already live never marks a successful publish as failed.
- Published-vintage gating for the new-vintage sensor. The refresh now records, inside the live database, the raw-input fingerprint it was built from, and the sensor fires only when the current inputs differ from that published fingerprint. Making the live database the authority (rather than querying run history) means a failed or still-queued run never suppresses a rebuild, a scheduled or manual run that promotes is seen regardless of launch path, and a restored older vintage is rebuilt rather than left stale while newer data is live. The sensor requires every input present, settles a changed fingerprint across two ticks instead of sleeping inline (an inline sleep blocked Dagster's shared sensor daemon), skips while a refresh is already queued or running, and is paired with a run-failure sensor that records failures for operators.
- Atomic, validated placement of raw inputs. `scripts/fetch_sources.py --place <files>` validates each downloaded geopackage and places a copy into data/raw/ with an atomic rename via a same-directory temp file, so the loader and the new-vintage sensor never read a half-written file. Validation opens the file with the GPKG driver specifically and reads one feature, so a truncated file, a WAF challenge page, a non-GeoPackage under a .gpkg name, or an empty geopackage is rejected; the staged copy (not the source) is the thing validated and promoted, so bytes that change mid-read cannot slip through. Both inputs can be placed in one command so they land as a consistent set rather than one new file beside one old one. The staged copy is made group/other readable so a loader or sensor running as a different account can read it, and the source download is left in place. The presence check likewise validates openability, not only a size floor.
- Atomic publish of the refresh. The loader and dbt build into a run-scoped side DuckDB file under build/staging/, the data-quality tests and the carry-over gate run against that side file, and it is promoted onto the live database with one atomic rename only after the whole build passes. A reader of the live database sees either the whole previous register or the whole new one, never a half-built, partially-tested or gate-rejected mixture; on any failure the side file is discarded and the live database is left untouched. The gate no longer drops tables in place, since the rejected register is a throwaway side file. The dbt profile path is now NFR_DUCKDB_PATH-overridable, defaulting to the live path so a plain make build is unchanged.
- Version-aware authoritative facility layer: v3.0 where it covers a state, v2.0 elsewhere, each row carrying its source version and current/stale status.
- Cross-version facility lineage as modelled, tested tables: a staging model (stg_version_lineage) that reconstructs each v2.0 facility against v3.0 by a mutual nearest-neighbour match within 100 m on lat/lon and classifies it carried-over, dropped or appeared with a match distance and a Jaro-Winkler name-similarity band, and a serving mart (lga_version_drift) that resolves the lineage against the canonical 774-LGA frame so it is queryable by LGA. Both carry enforced column contracts and tests: unique facility key, accepted status and name-band domains, a per-status field-shape check, a 100 m radius check on the built output, a grain-preservation check between staging and mart, and a fixture check that all three statuses are exercised.
- Per-LGA mart joining facility coverage to ESPEN soil-transmitted-helminths burden on the 774-LGA frame.
- DuckDB source loader and a two-stage dbt transform (staging, marts) with schema tests for the data contract.
- Unit tests pinning the LGA and state name-normalisation keys.
- CI running lint, unit tests and a dbt parse.
- Data contract for the published marts: DATA_CONTRACT.md documents the grain, keys, column types, nullability, value domains, the "missing is not zero" rule, and freshness/versioning. Enforced by dbt model contracts plus tests, including a 774-LGA row-count check and a composite (state, canonical_lga) uniqueness check on the coverage mart.
- Committed sample fixture (two states) so CI loads it and runs the full dbt build, proving the contract on every PR rather than only parsing. Toolchain pinned to Python 3.12 with a uv lockfile and dbt-duckdb 1.9.6.
- Dagster refresh pipeline: assets for the source load and the dbt build, a weekly schedule, and a sensor that rebuilds only when a new GRID3 vintage lands in data/raw/. Dagster is an optional install (the orchestration extra).
- Data-quality gate that fails a build or run on a fault, distinct from the observability checks that only warn. dbt tests block the build when the frame's distinct normalised (state, LGA) key count is not exactly 774, when a facility or reference table falls below a realistic lower bound on a production refresh (so a truncated-but-non-empty load is caught, not just an empty one), when the frame, the alias crosswalk or the NTD burden table has a duplicate normalised key (a duplicate burden row would multiply every LGA in its state through the coverage join) or a null crosswalk source key (which never joins), when the version-drift mart resolves an LGA the frame does not contain, or when the NTD burden table or the alias crosswalk carries a state the frame does not know. The NTD floor on a production refresh is the full 37-state set, so a dropped state is caught. The carry-over gate is enforced inside the dbt_models asset rather than as a downstream-only blocking check, so a collapse actually fails the refresh job; an undefined rate (no comparable v2.0 population) fails too, and the rejected mart and lineage tables are dropped in one transaction before the asset raises so no reader sees them and a partial failure cannot leave only some gone. A non-blocking asset check reports the gate's verdict on every completed build so consumers still get a check result, while the in-asset raise is the hard stop. The hard floor sits well under the advisory warn floor and the two are ordered so a vintage warns before it blocks. Every referential test normalises the state label on both sides so FCT is not a false orphan, and every anti-join uses NOT EXISTS so a null cannot make a check pass silently. The gate drops its output tables with fixed literal statements, so no value is interpolated or concatenated into SQL.
- Run observability on the refresh pipeline. Each run emits its figures as Dagster metadata: raw v2/v3 load counts, authority and lineage row counts, the LGA resolve rate for the coverage and drift marts, and the carry-over rate. Two non-blocking asset checks warn when the coverage resolve rate or the carry-over rate drops below an advisory floor, so a crosswalk regression or a bad load is visible without failing the run on normal vintage variation. The resolve rate is scoped to the states a vintage actually loaded, so it is comparable across the sample fixture and a national load, with the state label normalised on both sides so FCT is counted rather than dropped by a spelling mismatch. The carry-over rate is measured against the v2.0 facilities expected to carry (counted from the raw table before the lineage model's id and coordinate guards), so a facility lost to a bad load registers as a fall rather than vanishing from both sides of the ratio. The pre-dbt load count reads only the raw tables, so a fresh refresh does not fail querying staging tables that do not exist yet. A rate with a zero denominator reports as not-applicable rather than a misleading zero. The metric queries live in a separate module with unit tests covering the counts, the FCT normalisation, the lost-facility case, and the zero-denominator paths.
- Licensing split: AGPL-3.0-or-later code, CC BY derived artifacts, non-commercial terms carried for the derived ESPEN summary. Raw inputs fetched, not committed.
- LGA alias crosswalk mapping facility-source LGA spellings and former names to the canonical frame name, loaded and applied in the mart so a known variant joins instead of reporting zero.
- Coverage reporting to SonarCloud: pytest-cov emits coverage.xml, a sonar-project.properties uploads it, and CI runs the scan pinned to a commit SHA. Coverage reflects the unit-tested library code; the I/O loader and removed prototype scripts are not counted.

### Changed

- The publish step now has the same all-or-nothing cleanup as the build: if recording the published vintage or the atomic promote fails, the side database and the run snapshot are removed and the live register is left unchanged. The geopackage loader opens exactly the resolved path it checked against the project root, and CI fails on a `dbt deps` error instead of continuing.
- One canonical state label on the version-drift mart. `lga_version_drift.state` now always carries the frame's state name, resolved from the lineage state through `norm_state` and `frame_master_index` rather than taken from the LGA join, so records whose LGA does not resolve share the frame spelling with the rest of their state (FCT is `Federal Capital Territory` on every row). A filter or group-by on `state` now treats each state as one value. A new test, `assert_drift_state_in_frame`, fails the build if any `state` value is not spelled exactly as a frame state.
- Upgraded the orchestration and transform stack to current, advisory-clear versions: Dagster 1.9.5 -> 1.13.5 (webserver matched), dbt-duckdb 1.9.6 -> 1.11.1, and a dbt-core >=1.12 floor (resolving dbt-core 1.12.6, dbt-adapters 1.24.5, dbt-common 1.39.0), which lifts the transitive caps so sqlparse reaches 0.6.1 and deepdiff reaches 8.6.2. The two bumps travel together because dbt-core 1.12 requires protobuf 6, which only the newer Dagster line allows. The code location validates, the unit tests pass, and the full dbt build stays green on both the fixture and the real national inputs. This clears the full set of dependency advisories the older pins carried: ReDoS and DoS paths in sqlparse, class-pollution and memory-exhaustion paths in deepdiff, a path-traversal path in dbt-common, and the two Dagster I/O-manager paths.

### Fixed

- The data contract and architecture docs now match the shipped choropleth. DATA_CONTRACT.md covers all three serving marts, records `geometry_geojson` as `varchar` (not `json`), documents the `geometry_feature` column, and states the choropleth's real grain: one row per boundary polygon part (800 rows over the 774 LGAs), so coverage columns must not be summed across its rows. The architecture diagram now shows the vendored boundary polygons, the choropleth mart and the read-only Superset layer.
- A placed raw file is set to exactly mode 0o640 (owner read/write, group read, no world), so a sensor or loader account in the same group can read it without exposing the raw geopackages to every account on the host. The mode is set with os.chmod directly, which is not subject to the process umask, so group-read is guaranteed even under a restrictive umask (a umask-masked chmod would have stripped it under e.g. 0o040). Resolves a SonarQube file-permissions finding; tests pin the mode across a range of umasks.
- The Dagster dbt step and the Makefile build/test/sample targets run `python -m dbt.cli.main`, not `python -m dbt`: dbt ships no `dbt.__main__`, so the old invocation would have failed every orchestrated refresh and every `make build`/`make test` with "No module named dbt.__main__".
- The authority switch no longer drops every v2 fallback facility when the v3 source contains a null state, and canonicalises v2/v3 state-label aliases so a covered state is not duplicated or left with zero-count LGAs.
- Added tests for exact frame-key coverage, facility_status/source_version consistency, and both authority versions being present, so a dropped LGA, a contradictory coverage state, or a fixture that loses a path is caught.
- Source dates are the data vintage end dates, not publication dates, so freshness is never reported as a future date. The CSV loader parses deterministically, validates source paths resolve within the project, and loads all tables in one transaction.
- The lineage anti-joins are null-safe: dropped and appeared are computed with NOT EXISTS rather than NOT IN, and source ids are filtered non-null at the v2/v3 CTEs, so a null identifier can never empty the unmatched sets. Name similarity no longer coerces a null facility name to an empty string, so an absent name yields a null score and band rather than a spurious divergent classification. The version-drift mart keeps the unresolved source LGA label (source_lga) alongside canonical_lga and reduces the frame to one row per (state, LGA) key before joining, so an unresolved label stays visible and a duplicate frame row cannot fan out the lineage grain. The grain-preservation test compares the staging and mart facility-id sets in both directions instead of only row counts, and the all-statuses fixture check runs only on the sample build (var fixture_build) so a real refresh with fewer statuses is not rejected.

### Removed

- Three superseded prototype scripts (build_authority_layer, diff_versions, match_v2_v3_spatial) that nothing imported; the dbt models replace them.
